Parenthesis-free functions

Normally, to invoke a JavaScript function, you use parentheses. But perhaps you have strong objections to parentheses. Fine:

Object.prototype.message='alert\x281337\x29';Array.prototype.toString=Error.prototype.toString;Error.prepareStackTrace = Function;const x = new Error;x.valueOf=x.stack;+x;

This invokes alert(1337) without using parentheses in the code. The parentheses are smuggled into a string as hexadecimal escapes, which is spiritually different.

The mechanism is that Error.prepareStackTrace is called when an error's stack is accessed. It receives an error and an array representing the stack, which happens to resemble the signature of the Function constructor as long as you can turn that array into valid JavaScript. So you overwrite Array.prototype.toString, use Error.prototype.toString to manufacture the desired code, assign the resulting function to valueOf, and coerce the error into a primitive with +x. JavaScript sees a request to convert an error into a number and naturally executes arbitrary code.

This is not especially useful if you are writing normal JavaScript, where parentheses remain legal and considerably easier. But if someone has built a security filter whose core rule is "functions cannot be called without parentheses," JavaScript has once again discovered that syntax is more of a suggestion.

Scraping consent

Here is a content licensing model:

Meta's updated commercial terms say that users authorize it to deploy "web scrapers, bots, robots, spiders, crawlers, and user agents" against websites associated with their businesses, collect content from those sites, and use it to "research, train, and maintain" Meta products.

Virtually every news organization has a Meta business account, because that is how companies manage Facebook pages, Instagram profiles, WhatsApp channels and other commercial activity. So the arrangement is approximately: A publisher uses Meta to link to its website, and therefore Meta gets permission to copy the website.

Meta says this language consolidates permissions that were previously scattered across other terms and that publishers can still control access through robots.txt. Legal experts told Nieman Lab that the contract might let Meta argue that its scraping permission supersedes robots.txt. The terms also authorize Meta to create "test credentials," which James Grimmelmann says could technically let it "sign up as a fake user" to get through registration walls. Meta did not say whether that could include paywalls.

Publishers cannot opt out while continuing to use the covered business products. The terms instead say: "If you do not agree to the updated terms, please stop all access or use of our Products for business or commercial purposes." This is consent in the familiar modern sense where you may freely choose between agreeing and abandoning a distribution channel on which your audience is entrenched.

Also Meta has begun charging some accounts to post more external links. So publishers can pay Meta to link to articles that Meta can then crawl for free. It is vertical integration, if the vertical is "charging at both ends of the same hyperlink."

JavaScript Calls Functions Without Parentheses

blog.ikaes.de  ·  28 pts  ·  7 comments

A runtime hook, coercion, and a little prototype mischief turn an ordinary expression into executable code. It is less a practical idiom than a compact tour of JavaScript’s stranger machinery.

Read →Share →
[ Analysis + ]

Technical Analysis

The article describes a JavaScript technique for invoking arbitrary functions without visibly using parentheses. It abuses the nonstandard `Error.prepareStackTrace` hook, which can be assigned to the `Function` constructor, and manipulates array/string conversion—potentially through prototype pollution—to turn stack-trace data into executable code. The resulting function is triggered through coercion by overriding an object’s `valueOf` method, with the example ultimately displaying an alert. The technique is mainly relevant to JavaScript security research because it illustrates how obscure language features and prototype manipulation can bypass restrictions on function-call syntax, though it depends on particular runtime behavior.

Mapping Rome’s Economic Complexity

michelecoscia.com  ·  26 pts  ·  7 comments

A study turns geocoded Latin inscriptions and occupational records into an estimate of economic complexity across the Western Roman Empire.

The result tracks modern regional patterns, while the surviving evidence remains selective and heavily skewed toward elites.

Read →Share →
[ Analysis + ]

Technical Analysis

Researchers estimate the economic complexity of the Western Roman Empire by analyzing LIST, a geocoded database of Latin inscriptions that records people’s occupations. Because inscriptions disproportionately represent elite men, exclude most farmers and other workers, and reflect preservation and digitization choices, the study applies corrections to estimate occupational distributions across Roman provinces and modern geographic boundaries. These distributions produce Economic Complexity Index (ECI) scores, with Rome’s province of Latium ranking highest. The scores significantly correlate with modern ECI across roughly 23 corresponding countries, suggesting—but not proving—that economic complexity may persist geographically over very long periods.

Two Stacks Make Sliding Windows Simple

orlp.net  ·  33 pts  ·  1 comments

A pair of stacks supports constant-time aggregate queries and amortized constant-time updates, even when the operation has no inverse. The pattern handles sums, minima, quantiles, and approximate cardinalities without letting old numerical errors linger.

Read →Share →
[ Analysis + ]

Technical Analysis

The article presents a simple two-stack algorithm for computing aggregates such as sums, minima, means, quantiles, and approximate cardinalities over a sliding window, even when the aggregation operation has no inverse. It models aggregation with associative `empty`, `unit`, `combine`, and `finalize` functions, maintaining one stack for incoming values and another for cumulative aggregates as items leave the window. The method provides constant-time evaluation, amortized O(1) updates, and O(w) memory for a maximum window size, while supporting dynamically changing windows. It is particularly useful for floating-point or error-prone aggregates because values affect only windows that contain them, preventing stale NaNs, infinities, or accumulated numerical errors from persisting indefinitely.

RPKI Now Covers 70% of Internet Routes

ipinfo.io  ·  168 pts  ·  57 comments

Route-origin validation has reached 70.3% of Internet prefixes, up sharply from a year ago. The milestone is real, but broad authorizations and missing records still leave room for leaks and hijacks.

Read →Share →
[ Analysis + ]

Technical Analysis

The article reports that RPKI now validates 70.3% of Internet routing prefixes, up from 54% a year earlier, with much of the increase driven by China and growing IPv6 adoption. RPKI lets address holders authorize specific networks to originate their routes, and the data shows invalid announcements are now barely propagated because many networks reject them. However, RPKI only validates route origin: overly permissive ROAs can still allow valid-looking hijacks, and lost or missing ROAs leave networks unprotected without necessarily causing outages. The article also highlights early growth in ASPA, a complementary system intended to validate routing paths and detect leaks, while urging operators to publish complete ROAs, avoid broad `maxLength` settings, monitor authorization records, and document all upstream providers.

Technical Analysis

Folders is an esoteric programming language in which programs are represented entirely by the containment and alphabetical order of directories, with folder names otherwise ignored. Its simple imperative syntax encodes commands, expressions, variables, and types through the number and arrangement of child folders, while an interpreter stores temporary data in named folders. Inspired by Whitespace, the project explores code and data as filesystem structure rather than text, and includes Windows and Python implementations plus an online emulator and alternative visualizations. Its claims of effectively infinite storage reflect the conceptual experiment and filesystem behavior behind the language, not a practical replacement for conventional data storage.

Analysis

The essay argues that neural networks may be substantially more interpretable than the mechanistic-interpretability field has assumed. It revisits classic examples of polysemantic neurons and superposition, claiming they were often caused by architectural weaknesses, inadequate analysis tools, or ordinary hierarchical generalization rather than arbitrary feature entanglement. Drawing on newer vision and language-model studies, the author reports that most neurons appear to have one main function or closely related roles, with apparent mixtures often revealing meaningful shared patterns. This matters because it suggests researchers may be able to study models’ native neurons and circuits directly, rather than first reconstructing them with tools such as sparse autoencoders, potentially making interpretability research more tractable for understanding and auditing large AI systems.

The Folders Programming Language

danieltemkin.com  ·  84 pts  ·  11 comments  ·  discussion

Analysis

Folders is an esoteric programming language in which programs are represented entirely by the containment and alphabetical order of directories, with folder names otherwise ignored. Its simple imperative syntax encodes commands, expressions, variables, and types through the number and arrangement of child folders, while an interpreter stores temporary data in named folders. Inspired by Whitespace, the project explores code and data as filesystem structure rather than text, and includes Windows and Python implementations plus an online emulator and alternative visualizations. Its claims of effectively infinite storage reflect the conceptual experiment and filesystem behavior behind the language, not a practical replacement for conventional data storage.
