The HN Take

Answer pricing

DeepSeek now offers web search and page fetching for $0.75 per 1,000 successful requests. Search can return up to 50 results, including page content, and "count only controls how many results are returned and does not affect the per-request price."

Well sure, ask for 50.

The interesting pricing detail is that a request is billable only if it returns HTTP 200 and produces a result. Empty searches, failed fetches and timeouts are free. DeepSeek has invented an oracle that charges you only when the internet knows the answer. Knowledge costs $0.00075; ignorance is complimentary.

There are separate limits of five search requests and five fetch requests per second, so in theory you could make 864,000 successful requests per day for $648, assuming I have correctly multiplied numbers in a newsletter about artificial intelligence. A search request can include page content, while the fetch endpoint retrieves one page as Markdown. Economically, therefore, you should ask search for 50 pages at once and fetch only when you are feeling luxurious.

Also, server-side Search and Fetch calls made through DeepSeek Harness, Claude Code or Codex are currently free, with billing scheduled to begin on November 1. The product is already almost free, but for now it is more almost free.

Paranoid proofs

AI agents are apparently "very effective at finding vulnerabilities" in Lean's proof-checking kernel, so Lean now ships with several more kernels to check the checker. This is the natural endpoint of formal verification: You prove something, one kernel confirms it, four other kernels check the first kernel's work, and then everyone stares suspiciously at the compiler.

Lean's new "lake check --paranoid" mode rechecks a development with four additional kernels and a hardened version of the official kernel. One of them, con-leche, is written in Lean and was "implemented and proven consistent by Claude," under heavy human supervision. Then AI translated con-leche into Rust, and another Lean tool was used to prove that the Rust version refines the Lean version.

The logic is sensible. A verified Lean kernel might still be undermined by a bug in Lean's compiler or runtime. A corresponding Rust kernel is unlikely to have the same bug. So you run both and gain protection through implementation diversity. Formal certainty means asking two robots written in different languages whether the proof is valid.

There is also a normal sandboxed command, "lake check," and an option called "lake check --inadvisably-no-sandbox." I appreciate software that does not prevent you from doing the dangerous thing but makes you type out a small confession first.

Analysis

Researchers found that bleached *Pocillopora damicornis* coral can regain its symbiotic algae and recover within days or weeks when physically touching a healthy fragment from the same genetic individual. The fragments form a tissue bridge that allows algae to transfer, while separated fragments died and mismatched corals or fragments from different animals did not fuse. Analysis

Teal is a statically typed dialect of Lua that adds annotations and features such as arrays, maps, records, interfaces, union types, and generics while preserving Lua’s minimalism, portability, and embeddability. Its `tl` compiler translates `.tl` files into standard `.lua`, with Cyan for project builds and integrations for editors and language servers. It is significant as a TypeScript-like option for Lua developers who want compile-time checking and larger-project tooling without abandoning Lua’s ecosystem or runtime.

8. It's time to talk about TEEs

alinush.github.io | joshcsimmons | 3 points | 0 comments | discussion

First seen: October 18, 2026 | Consecutive daily streak: 1 day

Analysis

The article argues that trusted execution environments (TEEs), such as Intel SGX, AMD SEV-SNP, and Intel TDX, should not automatically be treated as secure places for valuable secrets or sensitive computation. It surveys failures involving enclave software bugs, forged remote-attestation reports, stolen attestation keys, physical memory-bus attacks, side channels, and platform or credential-revocation problems that can undermine confidentiality, integrity, or availability. These weaknesses matter commercially because applications often rely on attestation to trust remote hardware, yet verifying only generic vendor approval may allow a compromised machine to appear legitimate; tighter certificate pinning can help but adds difficult operational and PKI burdens. The author therefore recommends reassessing TEE threat models and avoiding reliance on them for high-value data, especially where physical access is plausible.
