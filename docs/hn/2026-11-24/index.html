Polymarket insider trading

Here is a prediction-market trade:

An anonymous Polymarket account bought 71,517.8 shares of "Will Jensen Huang rejoin NVIDIA by December 31, 2026?" at 6.5 cents each, spending 4,648.66 USDC. The account finished buying at 3:28 a.m. Central European time. Eighty-nine minutes later, Donald Trump posted on Truth Social that he hoped Nvidia's board would rehire Huang. Eleven hours after the purchases, Nvidia announced that it had unanimously voted to reinstate him. The shares paid out at $1, turning $4,648.66 into about $71,518.

Good trade!

The linked analysis calls this a "highly probable" case of insider trading. The circumstances are certainly suggestive. The account had been created 81 hours earlier, had traded exclusively on this Nvidia contract and absorbed 34% of the available sell-side liquidity at 6.5 cents in four concentrated orders. After completing the purchases, it stopped trading. This is not how you would behave if you had a vague feeling that perhaps Nvidia's board might reconsider eventually. It is how you might behave if someone texted you "they're bringing Jensen back tomorrow," though of course the blockchain does not record the text.

That last point is important. The analysis says that "the hypothesis of chance is statistically disqualified," but the public data show only that someone made an extremely well-timed bet. They do not show who the trader was, what the trader knew or where the information came from. Maybe the trader had inside information. Maybe the trader correctly inferred that a 33% stock decline would focus the board's mind. Maybe the trader is the world's best reader of presidential vibes. Prediction markets are markets in which people are paid for being right about unlikely events, so "this person made a lot of money by correctly predicting an unlikely event" is evidence of insider trading, but also the basic product description.

Still, the nice thing about alleged insider trading on Polymarket is that the suspicious trade is public immediately. In traditional markets, regulators have to subpoena brokers to find the person who bought the short-dated out-of-the-money options. On Polymarket, everyone can see the burner wallet buy the equivalent contract 89 minutes before the president posts. You don't know who did it, but you can watch them do it.

Prediction markets are supposed to reveal hidden information by turning it into prices. This one apparently worked perfectly. The hidden information became visible at 6.5 cents, to anyone who happened to be monitoring a newly created monomaniacal wallet in the middle of the night.

Browser inside browser

The browser is now an operating system, which is useful because it lets you run a browser.

Trynix.dev can run Nix packages directly in a web browser using Linux compiled to WebAssembly. The kernel and system components run at WebAssembly speed, while user programs are emulated. It supports networking, graphical applications and audio. Wayland surfaces are composited into the page, Mesa renders through WebGL2, and TCP connections travel over WebSockets. The new engine is reportedly between 2 and 32 times faster than the previous QEMU-based approach, depending on the workload.

Naturally the demonstration is Firefox running inside Firefox, loading trynix.dev and then loading Firefox again inside itself:

"Do not be too overjoyed. It took more than an hour for this to render."

Sure. The old joke was that JavaScript would eventually consume all software, culminating in a browser running another browser. Large language models have accelerated the schedule, and now Linux runs inside WebAssembly inside Firefox so that it can launch Firefox, which can run Linux inside WebAssembly and launch Firefox.

The computer industry spent decades moving applications into the browser. Having completed that project, it can now use the browser to recreate the computer that the browser replaced.

deucalionn.vercel.app  ·  103 pts  ·  43 comments

Technical Analysis

The article investigates a suspected insider-trading episode on Polymarket involving the market on whether NVIDIA CEO Jensen Huang would return by the end of 2026. It traces four Polygon transactions in which a newly created, single-purpose Gnosis Safe wallet bought about 71,518 contracts at a 6.5% implied probability for $4,648, completing the purchases 89 minutes before Donald Trump publicly supported Huang’s reinstatement and hours before NVIDIA announced it. fzakaria.com  ·  347 pts  ·  116 comments

Technical Analysis

The article describes trynix.dev, a browser-based environment that can run more than 300,000 Nix packages, including graphical, audio, and networked Linux applications. Its recent adoption of unkernel—a Linux system compiled to WebAssembly—replaces much of the slower QEMU emulation and improves performance by roughly 2–32 times. The platform can now run programs such as Solitaire, Firefox, and OpenGL demos, though complex workloads remain impractical, including a nested Firefox session that took over an hour to render. It is significant as a practical demonstration of software increasingly moving into JavaScript and WebAssembly environments, echoing the 2035 prediction in Gary Bernhardt’s talk but arriving much sooner.

Replay Turns Waiting Into a Performance Bug

fzakaria.com  ·  19 pts  ·  0 comments

Read →Share →
[ Analysis + ]

Technical Analysis

The article introduces Rewind’s new `rewind time` command, which analyzes deterministic VM recordings to identify a program’s critical path, sleeping and computing time, process dependencies, and likely performance improvements. Inspired by Brendan Gregg’s off-CPU profiling and flame graphs, it uses the scheduling and wakeup data Rewind already records for deterministic replay, avoiding the need to anticipate and trace a slow run. A libuv build example shows that although the run takes 78 seconds on one virtual CPU, its theoretical minimum is 47.4 seconds, with most critical-path time spent in sequential tests waiting on timers or events rather than consuming CPU. Users can drill from aggregated results into processes, source lines, Perfetto or flame-graph views, and replayable GDB sessions, making performance diagnosis reproducible and actionable.

Technical Analysis

Stalwart 1.2.0 adds Microsoft Exchange-compatible protocols—MAPI over HTTP, EWS, ActiveSync, and Autodiscover—so Outlook and common desktop and mobile clients can use its open-source, self-hosted mail, calendar, contact, task, and notes services. EPYC’s Decade Produces a 12.1× Leap

phoronix.com  ·  119 pts  ·  57 comments

A dual-socket 2017 EPYC system meets AMD’s modern Venice processors in a workload-based comparison. The geometric mean lands at 12.1×, with core counts, memory bandwidth, architecture, and power efficiency all contributing to the distance.

Read →Share →
[ Analysis + ]

Technical Analysis

Phoronix benchmarks AMD’s 2017 dual-socket EPYC 7601 “Naples” system against modern dual-socket EPYC 9006 “Venice” processors, including the 256-core EPYC 9996 and frequency-optimized EPYC 9686F. Across real-world workloads, the newer systems deliver a reported 12.1× geometric-mean performance increase, with gains reaching 133× in some AI tests, alongside major improvements in performance per watt. The comparison reflects nearly a decade of advances in core counts, cache, memory bandwidth, PCIe connectivity, instruction-set support, and architectural efficiency, although the platforms use substantially different memory and storage technologies. Its significance is that it quantifies how dramatically AMD’s server capabilities have evolved since entering the modern EPYC market, while highlighting the practical impact for datacenter performance and power costs.

Debian Rebuilds Its Bandwidth Toolkit

blog.daniel-baumann.ch  ·  120 pts  ·  8 comments

Debian splits iperf clients and servers into cleaner packages, adds templated systemd services, and introduces fireperf for parallel and bidirectional testing. The old package names remain as a compatibility bridge while the network bench gets modern plumbing.

Read →Share →
[ Analysis + ]

Technical Analysis

Debian has modernized its packaging of the iperf2 and iperf3 network bandwidth-testing tools by splitting client and server components into separate packages, adding systemd and UFW integration, and improving service isolation and upgrade handling. The new iperf3 server package supports multiple concurrently running instances through a systemd template, each using a distinct port, replacing the older debconf-based single-server setup. The changes are available in Debian sid and as trixie backports, while the legacy package names remain supported through transitional packages and compatibility provides. Debian has also introduced fireperf, an IPFire-based alternative that supports parallel clients, workers, and sessions, bidirectional testing, JSON and live-graph output, iperf/iperf3 compatibility, and more efficient operation.

Arctic Makes Concurrent Trees Less Compromised

usenix.org  ·  52 pts  ·  0 comments

Arctic is a lock-free adaptive radix tree designed to support updates alongside range and prefix scans.

Its freezing protocol and memory-reclamation scheme improve throughput in RocksDB and Turso, though its scans are not linearizable.

Read →Share →
[ Analysis + ]

Technical Analysis

Arctic is a lock-free adaptive radix tree designed to combine high performance, non-blocking updates, and range and prefix scans, capabilities that are difficult to provide together in concurrent indexes. Its freezing-based coordination protocol and metadata layout support lock-free operations, while a safe memory-reclamation scheme estimates reachable pointers using operation keys. The authors report that Arctic outperforms several lock-based indexes across many YCSB workloads, although its range and prefix scans are non-linearizable. Integrating it into RocksDB and Turso improved throughput by up to 40% and 12%, respectively, on write-heavy benchmarks compared with their default skiplist indexes.

No 04  ·  Editorial Op-Ed  ·  Performance Desk

Worshipping at the Altar of Brendan Gregg

fzakaria.com  ·  19 pts  ·  0 comments  ·  discussion

Analysis

The article introduces Rewind’s new `rewind time` command, which analyzes deterministic VM recordings to identify a program’s critical path, sleeping and computing time, process dependencies, and likely performance improvements. Inspired by Brendan Gregg’s off-CPU profiling and flame graphs, it uses the scheduling and wakeup data Rewind already records for deterministic replay, avoiding the need to anticipate and trace a slow run. A libuv build example shows that although the run takes 78 seconds on one virtual CPU, its theoretical minimum is 47.4 seconds, with most critical-path time spent in sequential tests waiting on timers or events rather than consuming CPU. Users can drill from aggregated results into processes, source lines, Perfetto or flame-graph views, and replayable GDB sessions, making performance diagnosis reproducible and actionable.

Modernizing iperf/iperf3 and introducing fireperf

blog.daniel-baumann.ch  ·  120 pts  ·  8 comments  ·  discussion

Analysis

Debian has modernized its packaging of the iperf2 and iperf3 network bandwidth-testing tools by splitting client and server components into separate packages, adding systemd and UFW integration, and improving service isolation and upgrade handling. The new iperf3 server package supports multiple concurrently running instances through a systemd template, each using a distinct port, replacing the older debconf-based single-server setup. The changes are available in Debian sid and as trixie backports, while the legacy package names remain supported through transitional packages and compatibility provides. Debian has also introduced fireperf, an IPFire-based alternative that supports parallel clients, workers, and sessions, bidirectional testing, JSON and live-graph output, iperf/iperf3 compatibility, and more efficient operation.

No 10  ·  Academic  ·  Systems Research

Arctic: A Practical Lock-Free Adaptive Radix Tree

usenix.org  ·  52 pts  ·  0 comments  ·  discussion

Analysis

Arctic is a lock-free adaptive radix tree designed to combine high performance, non-blocking updates, and range and prefix scans, capabilities that are difficult to provide together in concurrent indexes. Its freezing-based coordination protocol and metadata layout support lock-free operations, while a safe memory-reclamation scheme estimates reachable pointers using operation keys. The authors report that Arctic outperforms several lock-based indexes across many YCSB workloads, although its range and prefix scans are non-linearizable. Integrating it into RocksDB and Turso improved throughput by up to 40% and 12%, respectively, on write-heavy benchmarks compared with their default skiplist indexes.
