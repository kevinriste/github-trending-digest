The HN Take

Volume.

Here is a useful thing about the divergence theorem: If you want to know the volume inside a closed triangular mesh, you do not need to look inside it. You can walk around the outside, do a tiny calculation for each triangle, add up the answers and go home.

Alyssa Rosenzweig derives the algorithm:

"The final algorithm contains no numerical integration nor differentiation."

There is one loop over the triangles. For each triangle, there are seven additions and three multiplications. After the loop, one more multiplication. Rosenzweig estimates that a $35 Raspberry Pi could measure around 30 million triangles every frame in a 60-frames-per-second application.

This is the ideal outcome of advanced mathematics. You spend years learning triple integrals, vector fields and surface parametrizations, and eventually the mathematics tells you not to do the integral. The volume is notionally distributed throughout the entire three-dimensional object, but going into the object to count it would be gauche. Just ask each bit of the surface how much volume it is responsible for and total the invoices.

The post is titled "Hilariously Fast Volume Computation with the Divergence Theorem," followed immediately by "(No, there won't be jokes.)" The joke is that the divergence theorem has made the calculation too efficient to leave time for jokes.

Rosenzweig adds that she would be "pleasantly surprised" if the algorithm were novel. Further research found an earlier paper describing the same algorithm. You begin by calculating the volume of 30 million triangles per frame, one thing leads to another, and eventually you discover that someone already did it. Also the vector calculus exam is soon.

One byte.

Cloudflare's DNS platform stores more than 250 billion cache entries. At that scale, "wasting a single byte per entry costs more than 250 gigabytes of memory across our fleet."

This is a good general rule for large technology companies. At a normal company, wasting one byte is not a business problem. At Cloudflare, one unnecessary byte requires a meeting, a custom allocator and possibly several servers. Five changes to the memory layout of its DNS cache cut the size of each entry by more than half, freeing roughly 100 terabytes of memory, equivalent to the RAM in 130 of its servers.

Also the cache got faster. Insert throughput rose 43% and lookup latency fell 19%. Normally optimization involves a tradeoff where you use more memory to go faster or more computation to use less memory. Here Cloudflare removed a lot of unnecessary bookkeeping and the computers became both smaller and happier.

One example is Rust's growable list type. It keeps track of a pointer, the current length and the available capacity, because perhaps you will want to add more items later. But Cloudflare never modifies a DNS response after putting it in the cache. The capacity field was maintaining detailed plans for a future that would never arrive. Replacing growable lists and strings with fixed-size versions saved 64 bytes per cache entry, plus unused heap space, for more than 15 terabytes across the fleet.

Another problem was democratic representation. DNS records can contain many different kinds of data, and a Rust enum is sized to fit its largest possible variant. The largest record variant needed 136 bytes, so the full enum occupied 144 bytes. But more than 80% of Cloudflare's traffic consists of address records needing only 4 or 16 bytes. Every tiny address record was allocated enough room to imagine that it might someday become a much more elaborate record. It never would, but it had potential.

Cloudflare first moved the large variants into separate allocations. Then it found that the allocations themselves wasted space and scattered data around memory, so it stored record data as raw bytes in one contiguous buffer. This used less memory and improved locality. The sophisticated parsed object representation was replaced by a box of bytes, which is often where systems engineering ends up after an extended period of sophistication.

There is something pleasing about saving 100 terabytes without deleting any DNS answers. Cloudflare did not need fewer facts about the internet. It just needed each fact to stop bringing eight empty suitcases.

Analysis

This article presents a highly efficient $O(n)$ algorithm for calculating the volume of a closed, triangulated 3D mesh by applying the divergence theorem to convert a volume integral into a simplified surface integral. By expressing the volume as a sum of signed tetrahedral volumes defined by triangle vertices, the method replaces expensive numerical integration with a streamlined computation requiring only basic arithmetic. This approach is significantly faster than traditional sampling methods, enabling the processing of millions of triangles per frame even on low-power hardware like a Raspberry Pi. While the technique likely predates the author's derivation, it remains a vital optimization for performance-critical 3D graphics applications that require real-time geometric analysis.

2. Saving 100 terabytes of memory by optimizing 1.1.1.1's DNS cache

First seen: August 28, 2026 | Consecutive daily streak: 1 day

Analysis

Cloudflare recently optimized its "Big Pineapple" DNS infrastructure, which powers 1.1.1.1 and other services, by significantly reducing the memory footprint of its 250 billion cache entries. By implementing five key changes—such as replacing dynamic vectors with fixed-size boxes, packing bitflags, and storing DNS records in raw wire format—the engineering team successfully cut the per-entry memory footprint by over 50%. These technical refinements achieved a total reduction of 100 terabytes of system memory across their fleet while simultaneously improving insert throughput and lookup latency. This project is significant because it demonstrates how granular low-level memory management in Rust can yield substantial cost and performance gains at extreme scale, allowing the company to reinvest those resources into higher cache hit rates and improved service reliability.
