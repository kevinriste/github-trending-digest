Released, eventually.

PHP 8.6 has been released, in the expansive sense that it will be released later:

"PHP 8.6 Released.

Will be released on November 19, 2026"

The page then clarifies: "PHP 8.6 has not been released yet." Good. Software release status is complicated, and PHP 8.6 conveniently adds a clamp() function that ensures a value falls within a specified range. Unfortunately the range here appears to be "released" to "not released."

There is also a new Time\Duration class, representing elapsed time "as measured by a stopwatch," independent of time zones, with nanosecond precision across more than 250 years. This will let developers precisely measure the interval between PHP 8.6 being released and PHP 8.6 actually being released.

Other improvements include scalable polling, partial function application, structured stream errors and a standard SortDirection enum. Also using return inside a finally block is now deprecated because it can silently discard exceptions. PHP's language designers would prefer that control flow not announce one outcome and then quietly substitute another. The release page is apparently grandfathered in.

Twenty-one eszetts.

Here is a bad capitalization bug:

"Most of Ruby's single-byte encodings have no capital ß. Upcasing it writes two bytes, SS, but the loop only bounds-checks one."

Ruby allocates the output buffer with 20 extra bytes. Each ß expands from one byte to two, consuming one extra byte, so a string containing 21 of them writes one byte beyond the buffer. That one byte is enough, researchers say, to get unauthenticated remote code execution through stock Rails and classic-style Sinatra deployments running affected Ruby versions.

The bug has existed since Ruby 2.4.0. UTF-8 strings use another code path and are unaffected, but several older ISO-8859 and Windows-125x encodings reach the vulnerable loop through upcase, swapcase, downcase(:fold) and casecmp?.

So the security boundary is straightforward: Twenty German letters are text processing. Twenty-one German letters are server administration.

Fixed releases are Ruby 3.3.14, 3.4.13 and 4.0.10. Ruby 3.2 and older are affected back to 2.4.0 and are end-of-life, which means their official remediation strategy is aging out of the problem. The researchers plan to publish a proof of concept in a week, after people have had time to upgrade. Capitalization will then become considerably more urgent.

PHP 8.6 brings partial application, nanosecond durations, native polling, and stricter APIs. Migration work follows: several legacy behaviors and interfaces are leaving the runtime behind.

Technical Analysis

The story announces PHP 8.6, scheduled for release on November 19, 2026, as a major update focused on more expressive code, stronger typing, and scalable I/O. Its headline features include partial function application, a nanosecond-precise `Time\Duration` class, the `Io\Poll` API using native mechanisms such as epoll and kqueue, a generic `clamp()` function, and the type-safe `SortDirection` enum. The release also adds structured stream errors, readonly property defaults, expanded reflection and URI APIs, cryptographic and TLS improvements, and various performance optimizations. It is important for developers and library authors because it improves concurrency foundations and API consistency while introducing deprecations and behavior changes—including stricter sessions, validation, error handling, and removal of outdated interfaces—that may require migration work.

Ruby’s ß Bug Opens Rails to RCE

verialabs.com  ·  178 pts  ·  68 comments

A one-byte heap overflow in legacy encoding handling turns attacker-controlled text into a pre-authentication remote-code-execution path. Upgrade Ruby immediately; unsupported 3.2 and older releases remain exposed.

Read →Share →
[ Analysis + ]

Technical Analysis

Ruby2Shell (GHSA-34m4-m9fh-gqp5) is a critical, unauthenticated remote-code-execution vulnerability in Ruby’s case-conversion handling for certain legacy single-byte encodings. An off-by-one heap overflow occurs when characters such as “ß” expand during operations like `upcase`, potentially enabling exploitation through applications that process attacker-controlled strings. Rails and classic Sinatra are exposed in their default configurations, and affected Ruby versions are bundled with products including GitLab, GitHub Enterprise Server, and Chatwoot. Organizations should upgrade Ruby to 3.3.14, 3.4.13, or 4.0.10, or install vendor-fixed releases; Ruby 3.2 and older are end-of-life.

SQLite Shards Turn Blobs Into a System

zerodha.tech  ·  82 pts  ·  14 comments

Blobasaur replaces a brittle single-node store with sharded SQLite, Rust, compression, and careful batching. The result is roughly 2 ms p99 latency on three nodes—an economical answer to a very specific workload.

Read →Share →
[ Analysis + ]

Technical Analysis

Zerodha built Blobasaur, an open-source Rust server that uses sharded SQLite databases to store high-throughput, variably sized JSON blobs for Kite users’ layouts, preferences, and workspace metadata. It replaces the unmaintained, single-node SSDB, while avoiding the cost, latency, operational complexity, or poor overwrite behavior the team found in alternatives such as cloud object storage, distributed databases, and raw filesystems. Blobasaur maintains Redis and Redis Cluster compatibility, compresses payloads with zstd, supports TTLs and relaxed durability, and scales through per-node SQLite shards and multi-node hash-slot partitioning. Production results on a three-node cluster show roughly 2 ms p99 latency, illustrating how carefully designed SQLite sharding and batching can provide an economical solution for non-critical but demanding blob workloads.

NGINX HTTP/2 Bugs Put Gateways at Risk

wiz.io  ·  1412 pts  ·  606 comments

Two unauthenticated memory-corruption flaws can turn an ordinary NGINX gateway into an entry point for code execution. Patch fixed releases now, or disable HTTP/2 while internet-facing systems move to the front of the queue.

Read →Share →
[ Analysis + ]

Technical Analysis

The story covers two critical, unauthenticated remote-code-execution vulnerabilities in NGINX’s HTTP/2 handling: a connection use-after-free (CVE-2026-123633) and a flow-control integer-underflow memory-corruption flaw (CVE-2026-123007). Because NGINX commonly serves as a shared web gateway, reverse proxy, load balancer, or static-file server, exploiting either issue could compromise multiple websites and APIs even when their application code is secure. Both require HTTP/2 to be enabled, with the older flaw affecting versions back to 1.9.5, and researchers demonstrated code execution against standard configurations. Administrators should upgrade to fixed releases—NGINX OSS 1.30.7 or 1.31.9, as applicable—or temporarily disable HTTP/2 while prioritizing internet-facing systems.

Analysis

The story covers two critical, unauthenticated remote-code-execution vulnerabilities in NGINX’s HTTP/2 handling: a connection use-after-free (CVE-2026-123633) and a flow-control integer-underflow memory-corruption flaw (CVE-2026-123007). Because NGINX commonly serves as a shared web gateway, reverse proxy, load balancer, or static-file server, exploiting either issue could compromise multiple websites and APIs even when their application code is secure. Both require HTTP/2 to be enabled, with the older flaw affecting versions back to 1.9.5, and researchers demonstrated code execution against standard configurations. Administrators should upgrade to fixed releases—NGINX OSS 1.30.7 or 1.31.9, as applicable—or temporarily disable HTTP/2 while prioritizing internet-facing systems.

15M web servers on one VM – smoltcp, DPDK, AF_XDP

kapteko.com  ·  190 pts  ·  26 comments  ·  discussion

Analysis

The article explores whether 15 million minimal web servers can run on one VM with 10 GB of RAM and a single CPU core, exposing the resource costs of ordinary processes and Linux’s kernel networking stack. After finding that ports, process memory, and roughly 3.3 KB of kernel state per socket make the conventional approach impractical, it proposes a custom user-space runtime with lightweight scheduling and sandboxing. The runtime uses the Rust smoltcp TCP/IP stack with DPDK or AF_XDP to bypass most kernel networking overhead, reducing idle-server memory to about 620 bytes and demonstrating more than 16 million servers in a proof of concept. The broader significance is that specialized runtimes and user-space networking can drastically improve connection density and control, though achieving full POSIX compatibility and production reliability would require substantial additional engineering.

No 10  ·  Notebook  ·  Practical Computing

Do not buy RAM, compress

curiousbits.nl  ·  51 pts  ·  38 comments  ·  discussion

Analysis

The article argues that Linux users should consider enabling zram, which compresses memory and uses it as a form of swap, before buying additional RAM. Compression adds modest CPU overhead and latency, but can substantially increase effective memory capacity, with the author measuring 5.7 GB of data stored in 1.7 GB of RAM—a 3.35:1 ratio—while opening many browser tabs. Although Windows, macOS, Android, and some Linux distributions enable memory compression by default, Ubuntu and many other environments do not. The technique could extend the useful life of fixed-memory workstations and reduce cloud costs by delaying or avoiding larger machine upgrades.
