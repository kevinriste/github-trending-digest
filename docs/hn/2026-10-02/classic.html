The HN Take

Minimal Pi

Here is a software development strategy:

Pi, the coding-agent harness, is known for being minimal. Agent tooling changes constantly, and its developers do not want to add every fashionable feature. Instead, they wait until features have "proven" themselves, weigh their functionality against their complexity, and only then add them.

Today Pi 1.0 adds native MCP support, virtual models, deferred tool loading, Anthropic cache warming, mid-conversation system messages, a new terminal theme and full-screen mode by default.

Sure. Minimalism does not mean having few features. It means having rejected even more features than you accepted. "The list of things that fell off the wall is much longer," the developers write. Minimalism is a counterfactual property.

There was, however, another problem. Pi runs in a terminal, on one machine, for one person. Some users wanted agents that could run elsewhere, conduct longer tasks, survive failures and be steered by multiple people. Adding all that to Pi would make Pi less minimal. So Earendil built a separate experimental package, Pi Durable, for "long-running, durable, and malleable agents that can run anywhere."

This is the cleanest way to preserve minimal software. Whenever users request a large complicated set of features, you do not put them in the minimal product. You build another product containing the large complicated set of features. The original remains minimal, and your total system becomes larger.

Pi Durable stores conversations and tasks so agents can recover after crashes. If a model request is interrupted, it is sent again; if a tool call is interrupted, it is rerun when safe, or reported back to the model when it isn't. A request ID makes retries exactly-once. It can also run multiple conversations concurrently, fork conversations from earlier points and give different conversations different models, tools and execution environments.

This is all sensible infrastructure for agents that do real work. If your coding chatbot crashes, you sigh and restart it. If your autonomous agent crashes halfway through deploying software, sending messages and modifying files, "just run it again" is less obviously good operational advice. Pi Durable is meant to know which parts can safely happen twice.

The whole source code, excluding tests, is about 15,000 lines, which Earendil estimates at about 150,000 GPT tokens or 250,000 Claude tokens. The point is that an agent can understand the software running the agent. We have arrived at a new definition of minimalism: The system is minimal if the artificial intelligence operating it can fit the whole thing in its context window.

Decision models

Large language models are useful because you can ask them an open-ended question and they will produce an open-ended answer. Large language models are troublesome because you can ask them a yes-or-no question and they will produce an open-ended answer.

Cloudflare has a solution:

"A decision model makes classifications to help agents decide how to act, based on certain probabilities."

Cloudflare today released Clef and Clef-flash, two open-weight decision models that take inputs and return bounded, typed outputs with probabilities. You can give one a support message and ask whether it is urgent, which team should handle it and how severe it is. Your software can then route the ticket without first parsing three paragraphs about the nuanced nature of urgency.

The basic pitch is that LLMs are good for reasoning and generating text, but not every part of a workflow needs reasoning and text. Sometimes the machine needs to choose "billing," "technical" or "sales." You could ask a general-purpose model to do that, but then it has to generate the answer token by token, creating both latency and the possibility that it chooses "billing, although on reflection this situation raises broader questions."

Clef instead scores the valid schema choices in parallel. Cloudflare says the decision step is non-autoregressive and produces no intermediate text. In one internal domain-classification workflow, Clef took 2.2 seconds to fetch, render and classify a website, while gpt-oss-120b took 4.7 seconds and returned only two classifications.

This is a natural stage in the development of artificial intelligence. First we built models that could write anything. Then we discovered that, for many business applications, writing anything is exactly the risk. So now we are building models whose main feature is that they are physically incapable of going off on a tangent.

Cloudflare says these models mean "a human does not necessarily need to be in the loop for agentic decisions anymore." Right. The human was previously in the loop partly because the model might return something weird. If the model can only return one of the approved boxes on the form, the human can leave. We automated judgment by turning it back into a dropdown menu.

The flaws may enable privilege escalation, denial of service, or information disclosure, depending on the affected configuration and attack conditions. Analysis

Cloudflare introduced Clef and Clef-Flash, open-weight, Apache 2.0 decision models designed to produce fast, typed classifications and calibrated probabilities for routing, tool selection, and other agent workflows. Based on Qwen and using schema-bound, non-autoregressive scoring rather than token-by-token generation, the models support text and images, offer larger context than some competitors, and are available through Workers AI or locally via Hugging Face. Cloudflare says Clef performs competitively on decision benchmarks and can reduce latency compared with general-purpose LLMs, while its edge deployment avoids storing or training on customer data by default. The company also launched a hands-on reinforcement-learning fine-tuning service, with plans for self-service training and redeployment using data collected through its AI platform, targeting specialized workloads such as support triage, threat intelligence, and safety classification.

Analysis

SvelteKit 3, the latest version of Svelte’s official application framework, has been released with incremental improvements focused on polish, type safety, simpler configuration, and reduced boilerplate.
