Weight-space programming

The normal way to improve a neural network is to train it. You give it examples or rewards, calculate how wrong it was, use an optimizer to adjust millions or billions of inscrutable numbers, and repeat until it becomes useful or the electricity bill becomes embarrassing.

Here is a different approach: Ask another neural network to look at the inscrutable numbers and fix them.

Researchers report that GPT-6 Astra can inspect raw network weights and infer what the network does, without running it. Given four identically shaped policies trained on different games, it correctly named each game. Given the middle layers of small language models, with the input and output layers removed, it identified whether they had been trained on Python, romaji or English, and found every copying head without falsely naming any others.

Then they let it edit the weights:

"Asked to make Qwen3.5-0.8B better at math without gradients, Astra identifies an issue in its weights causing reasoning loops that Qwen's own model card warns about, and fixes this by natively editing 0.016% of the weights."

With the same sampling settings, the edited model's MATH-500 score reportedly rose from 7.9% to 48.1%, while its IFEval score tripled. This was not conventional fine-tuning. Astra was not allowed to write a training loop. It apparently inspected Qwen's brain, found the part that made it pace around muttering the same reasoning, and adjusted a few neurons until it stopped.

The authors call this "Weight-Space Programming." The idea is that neural-network weights are not merely an enormous pile of numbers to be nudged statistically by Adam or Muon. They are a program, and a sufficiently capable language model can read and write that program directly.

On small games, Astra reportedly wrote entire networks from scratch. Its one-shot Breakout network scored 517.4, versus 15.8 for a PPO network trained for 100 million steps and 25.3 for one trained for 500 million steps. The explanation is reasonably intuitive: Instead of spending 500 million steps discovering that the paddle should move toward where the ball will land, Astra programmed one layer to estimate where the ball would land and another to move the paddle there.

This is cheating only in the sense that understanding the assignment is cheating.

The results are early, and the small-network experiments are particularly friendly to direct inspection: Astra could find spatial patterns in first-layer weights or see shapes drawn in output-layer weights. But the Qwen result is the interesting escalation. If it generalizes, the future of model training could involve less blind optimization and more model management. One model notices that another model has a bad habit, opens its skull, changes 0.016% of its personality and sends it back to work.

For years, the concern has been that humans cannot understand what neural networks are doing internally. One possible solution, apparently, is to hire a neural network to explain the neural network. If it cannot explain it, it can just repair it.

Auto Ontology

Nvidia has open-sourced Auto Ontology, a system for teaching AI agents what a company's data means.

This is an actual problem. An agent can generate SQL quickly, but if one database defines "revenue" as booked revenue, another defines it as collected cash and a third includes something maintained by Craig in a spreadsheet, then faster answers merely produce wrong numbers more efficiently. Nvidia puts it nicely:

"A revenue metric answered faster is worth nothing if the number is wrong."

Auto Ontology builds a semantic layer from enterprise metadata, reconciles definitions across systems, checks generated queries against certified definitions and lineage, and returns provenance with answers. It tells agents "where data lives, what it means, whether to use it, how to use it, where it came from, and what is similar."

This is roughly a corporate dictionary, except the dictionary is connected to Snowflake and allowed to execute queries.

The library is distributed under Apache 2.0 and exposes its context through MCP, CLI and API. It is open source, though the repository notes that it is "currently not accepting external contributions." Anyone can inspect and use the corporate dictionary; Nvidia is not presently accepting suggested definitions.

There is also an excellent operational detail. Connections added through the user interface need credentials. If Vault is configured, those credentials go into Vault. If Vault is not configured:

"The full connection object (including the password) is JSON-serialized and stored, unencrypted, on the catalog's database row."

And if Vault is only partly configured, the partial configuration is ignored with a warning and the system falls back to plaintext storage.

This is disclosed clearly, and there are perfectly reasonable local-development uses for it. Still, there is something very enterprise-software about building an elaborate knowledge layer so that every answer has certified meaning and provenance, while storing the password to the source database in plaintext unless the user successfully fills in every Vault environment variable.

The agent will know exactly what revenue means. Whoever reads the Postgres row will know exactly where revenue lives.

Astra Edits Model Weights by Hand

rikiyat.github.io  ·  2749 pts  ·  834 comments

Astra experiments with a strange new interface to neural networks: natural-language instructions aimed directly at their weights. The early results are narrow but notable, improving Qwen3.5-0.8B after changing just 0.016 percent of its parameters.

Read →Share →
[ Analysis + ]

Technical Analysis

The article presents early experiments in “Weight-Space Programming,” in which a frontier LLM directly inspects and edits neural-network weights using natural-language goals rather than gradient descent or conventional training loops. The model reportedly inferred what small networks had learned, generated game-playing networks from scratch, diagnosed behavioral traits, and improved Qwen3.5-0.8B by changing just 0.016% of its weights, substantially raising math and instruction-following scores by reducing reasoning loops. However, it could not reliably identify sycophancy from weights alone or improve a smaller model whose limitations reflected missing reasoning ability rather than a localized defect. The work is important because it suggests a possible future tool for targeted model debugging, interpretability, capability editing, and lower-cost optimization, though the results are preliminary and depend on specialized prompts, harnesses, and evaluation setups.

NVIDIA Opens an Ontology for Enterprise Data

github.com  ·  104 pts  ·  32 comments

Auto Ontology builds a semantic layer from database metadata, then exposes it through APIs, a CLI, and an MCP server. It promises cleaner agent-assisted analytics; credentials stored in plaintext by default suggest a less-clean deployment story.

Read →Share →
[ Analysis + ]

Technical Analysis

NVIDIA’s open-source Auto Ontology is a platform for building an enterprise semantic layer from database metadata, reconciling inconsistent business definitions, and providing agents with trusted context for analytics. It supports natural-language-to-SQL querying, lineage and provenance, validation against certified metrics, and continual learning from corrections, exposing these capabilities through a web UI, API, CLI, and MCP server. The stack uses FastAPI, Next.js, Postgres/pgvector, LangChain, and NVIDIA NIM models, and can run via Docker Compose or Kubernetes against systems such as Postgres, Snowflake, Databricks, and DuckDB. It is Apache 2.0 licensed but currently closed to external contributions, requires NVIDIA model access by default, and should be deployed carefully because UI-added database credentials are stored in plaintext unless Vault is configured.

This Tool Burns Pictures Into Optical Discs

github.com  ·  253 pts  ·  51 comments

DiscImageStudio converts images into the physical patterns that CD, DVD, and Blu-ray burners can record. Calibration, dithering, simulation, and experimental direct burning turn obsolete media into a low-resolution canvas.

Read →Share →
[ Analysis + ]

Technical Analysis

DiscImageStudio is an open-source GPL-licensed C# tool that converts images into data conforming to the physical recording constraints of CD-R, DVD-R, and single-layer BD-R media, producing visible artwork when burned. Its Windows GUI supports layered design, tone and dithering adjustments, calibration, previews, ISO/RAW/WAV+CUE export, and experimental direct burning, while Linux and macOS offer experimental command-line image generation. The project also supports mixed data discs, disc-specific presets, readback simulation, and detailed modeling of optical-disc encoding, geometry, error correction, and file systems. It is notable because it turns ordinary recordable media into a low-resolution physical display, though results depend heavily on the disc, burner, firmware, calibration, and still-limited validation of its experimental burning features.

Europe Builds a Long-Lived RISC-V Stack

erici.eu  ·  136 pts  ·  72 comments

ERICI proposes an open reference platform for industrial computers built around the RVA23 RISC-V profile. Firmware, hypervisors, real-time software, and Linux are designed to coexist on hardware expected to remain supportable for 10 to 15 years.

Read →Share →
[ Analysis + ]

Technical Analysis

The European RISC-V Industrial Computing Initiative (ERICI) is a non-commercial, Europe-based effort to create an open reference platform for long-lived industrial computers using the RVA23 RISC-V profile. It aims to connect firmware, boot loaders, a partitioning hypervisor, real-time software, and Linux into a verified stack that can run side-by-side on compliant hardware, while defining open interfaces between layers. The initiative addresses the gap between newly available RVA23 development boards and industrial systems that also require rugged hardware, fieldbus and real-time I/O, certifications, watchdogs, and 10–15 years of availability. Its importance is reducing dependence on x86 and Arm licensing and vendor roadmaps, while breaking the cycle in which hardware makers wait for software and software developers wait for suitable hardware.
