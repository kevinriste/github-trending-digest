Destination toilets

Norway has apparently solved public infrastructure:

"These toilets are worth a visit, both when you really have to go and when you don't."

The Norwegian Scenic Routes include architect-designed restrooms overlooking fjords, waterfalls and Arctic landscapes. One has windows onto the Aurlandsfjord, so "if the queue is unusually slow, it's most likely someone taking pictures." Another is solar-powered. Another is designed to grow moss on its walls. A forthcoming forest-inspired restroom will use dried wood from 60 to 70 trees and look like "an upside-down tree trunk with roots holding the roof."

Sure. The normal economic purpose of a public toilet is that people need to use the toilet. The upgraded Norwegian model is that people who do not need to use the toilet visit anyway, causing lines for people who do. This is a successful tourist attraction, though arguably a less successful toilet.

There is even a golden loo on Senja that is so popular that "several other (more low-key) toilets will be built nearby." You build one spectacular toilet to meet a biological need, tourists arrive to photograph it, and then you need to build several ordinary toilets to handle the demand created by the spectacular toilet. Eventually Norway will be covered in public restrooms, most of them serving people waiting to see the public restrooms.

HackerTube

Here is one solution to algorithmic slop:

"It was Friday night at 11pm, I was tired, I went to YouTube to watch something and realized that I was looking at an enshittified wall of slop."

So the author asked Claude Opus 5.5 to build a different YouTube interface using videos recommended in Hacker News comments. Opus downloaded the comments, filtered them, used Sonnet to identify recommendations, found 6,454 videos across 150 topics, built the interface, acquired a server deployment and produced HackerTube.

"This takes ~2 hours now. I can breathe again."

There is an appealing circularity here. A giant recommendation system produces an unbearable wall of content, so you ask an AI agent to scrape 19 years of recommendations made by humans and build you a replacement recommendation system. The AI's job is to recover human taste from before the AI era.

The author adds:

"I don't actually do anything resembling traditional engineering anymore (read/write code, run commands in a terminal, or etc.), I only talk to Claude and have it do everything."

The remaining manual work was creating a Google Cloud API key, booting a VPS and buying the domain. So traditional engineering has been automated away, leaving the irreducibly human work of clicking through cloud dashboards and entering a credit card number. Progress.

atlasum.net | oger | 539 points | 249 comments | discussion

Analysis

The story examines CVE-2026-98432, a critical Linux IPv4 TCP-handshake use-after-free affecting kernels dating back to 4.4, which can potentially enable unauthenticated remote memory disclosure, crashes, or code execution before applications receive a connection. Upstream fixes are available across supported kernel branches, but distribution kernels—particularly Ubuntu and RHEL as of October 31, 2026—had not yet shipped fixes, creating operational risk for internet-facing servers, container hosts, and Kubernetes nodes. Anthropic reports that Claude developed a working remote-root exploit for systems with multipath TCP listeners, which are enabled by default for some newer Go programs, although the exploit has not been publicly released. Administrators should identify affected distribution kernels, install and reboot into fixed versions, and use temporary mitigations such as blocking IPv4 TCP packets with options or disabling multipath TCP where patching is delayed.
