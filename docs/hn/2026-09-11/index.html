Native AI

Shopify is moving its mobile apps from React Native back to Swift and Kotlin because artificial intelligence has changed the economics of writing the same software twice:

"By late 2025, they were no longer just helping us write code faster. They were capable of making us question whether building software twice still meant doing twice the work."

The traditional argument for React Native is straightforward. Apple and Android have different native development environments, but merchants generally want the same button to work on both. You can have two teams build the button twice, or one team build it once in a cross-platform framework. One is more work than two, in this particular counting system.

But coding agents can now implement an Android feature using the iOS version as a reference, and vice versa. So Shopify's calculation is that it can return to building every feature twice while no longer doing twice as much human work. The agents do much of the implementation and translation, while Shopify gets closer access to each platform's native capabilities and avoids some framework and dependency layers. AI has made duplication efficient enough to beat code reuse.

This does not mean that Shopify points an agent at the old app and returns after lunch to find two polished native apps. That produces "a huge amount of unmaintainable code that can't be shipped." Instead Shopify built a system called Helix that divides each screen into small checkpoints. Each checkpoint needs tests, a visual comparison with the existing app, reviews from two adversarial code reviewers and human approval before the agent can proceed.

So the new efficiency is roughly: Instead of humans writing one implementation, agents write two implementations while humans, tests and two hostile robot supervisors repeatedly stop them from doing anything terrible. Apparently this is faster. Shopify says its Shop team rebuilt the native app in 12 weeks.

The more interesting part might be that Shopify is redesigning its app architecture for the agents. Business logic can run headlessly on desktop and is exposed through a command-line interface, allowing agents to inspect app state, navigate and perform actions without slowly poking at a simulator. The apps are still for merchants and buyers, but the architecture is now also optimized for the other important user: the computer that writes the app.

Same model

OpenRouter lets developers request an open-source AI model and routes the request to one of the companies hosting it. In theory, the model is the weights, so the same model should be the same model wherever it runs. In practice:

"They're the same model on paper, but very different models in real life."

Mo Moustafa, who runs an AI assistant that has processed more than 18 million messages, describes the consequences. One provider running DeepSeek V4 Flash scored 90% on one benchmark and 81% on another; another provider serving the same weights scored 75% and 58%. Some providers hosting vision models misread simple images, while others apparently did not see the images at all but still returned "200 OK." Some accept a reasoning-effort setting without necessarily doing anything with it. Some fail to parse tool calls and return the raw markup as text. Some return hundreds of completion tokens, a successful status and no answer.

This is a useful clarification of what an AI model is. There are the weights, and then there is the precision, infrastructure, parser, rate limiting, API behavior and assorted proprietary optimization applied by whoever happens to be running the weights. Asking for a model is a bit like ordering a standardized product and receiving one of 20 locally interpreted versions of it, several of which occasionally arrive empty but with a receipt confirming successful delivery.

The obvious solution is to choose reliable providers and disable fallback. Moustafa tried that with three providers. Then one stopped serving the model, another began rate-limiting everything, all the traffic moved to the third, and that one began rate-limiting too.

The point of a router is that you do not need to depend on one provider. The point of pinning providers is that you cannot depend on the router's providers. Eventually you obtain a carefully diversified portfolio of failures.

Visualizing Particles Faster Than Light

iaea.org  ·  66 pts  ·  46 comments

When charged particles traverse dense mediums like water, they emit a signature blue glow as they break the local speed of light. This phenomenon, known as Cherenkov radiation, offers nuclear inspectors a precise, non-invasive method for monitoring spent fuel reserves.

Read →Share →
[ Analysis + ]

Technical Analysis

Cherenkov radiation is the blue glow produced when charged particles travel faster than light through a medium, an effect analogous to a sonic boom that earned Pavel Cherenkov a Nobel Prize in 1958. While the speed of light in a vacuum remains an absolute limit, particles can exceed the speed of light within denser materials like water, causing atoms to emit visible blue or ultraviolet photons to restore equilibrium. Today, the International Atomic Energy Agency (IAEA) utilizes specialized viewing devices to detect this radiation in spent nuclear fuel storage ponds. By measuring this glow, inspectors can verify the quantity of stored nuclear material, serving as a critical safeguard to ensure that radioactive components are not diverted for non-peaceful purposes.
