The HN Take

123456

Here is one approach to protecting a national identity database:

At least three user accounts at the Funen-based IT company Pays used the password "123456" when hackers gained access to Denmark's CPR register, Politiken reports.

One of them was the company's administrator account.

The breach exposed information linked to around 8.8 million CPR numbers. Jens Myrup Pedersen, a professor at Aarhus University, called the password security "hopeless":

"There is really no security, it is an open door. A password like '123456' is one of the very first things you would guess if you took a list of common passwords."

Yes. In computer security there is a complicated ongoing contest between attackers and defenders involving zero-day vulnerabilities, cryptography, artificial intelligence and highly sophisticated social engineering. There is also typing "123456" into the administrator login. You would perhaps start with that one.

Denmark's CPR register contains personal information about people living or previously registered in the country. Private companies can receive access when they have a legitimate need, for instance to look up customer addresses. This is sensible enough: A useful central database has to be usable. But then the security model for the central database becomes approximately "every small company with legitimate access must secure that access." Pays had two employees as of July. At least three of its accounts reportedly had the password "123456." There were more copies of the password than there were employees.

The hacker reportedly got in using a leaked password belonging to a former employee, then built two programs to retrieve and store CPR information. The access lasted 21 days and 17 hours. The hacker said that gaining access "had not been particularly difficult" and that there were no plans to sell or publish the information.

Fine. Denmark constructed a central civil register covering millions of people, carefully limited access to organizations with legitimate needs, and one of those organizations secured its administrator account with the password used to demonstrate bad passwords. The hacker apparently does not plan to misuse the data. That is fortunate, because the main remaining control was politeness.

Semicolon

Telegram Desktop had a semicolon problem.

When you click a Telegram link while Telegram is already running, the operating system launches a second instance of the application. That instance sends the link to the first instance over a local socket and exits. Telegram serializes commands as text, with semicolons separating them. It did not escape semicolons inside the links.

So a link that Telegram's new process regarded as one URL could arrive at the running process as several commands. The security researcher who found the vulnerability writes:

"The new process treats it as a single URL, because to it that semicolon is just a character inside the query."

The existing process then "cuts at every semicolon and gets two instructions instead of one."

This is the standard problem with inventing your own tiny command language. You decide that semicolons separate commands. Later you allow users to supply text containing semicolons. The computer faithfully concludes that the users are supplying commands. Computers are literal in ways that are useful until they are extremely not.

On its own, command injection was not enough for account takeover. But Telegram also had an internal URI scheme called "interpret:" that had been built to automate publishing Telegram releases. An instruction file could specify a channel, a local file and a caption, and Telegram would read the local file and send it to the channel. This was meant for Telegram's own release process, and it performed "no authorization check."

Again, considered locally, this made some sense. If an attacker can already launch Telegram from your computer with a local instruction file, the attacker probably has access to your files anyway. But the semicolon bug made the internal feature reachable from a clicked link. Two individually manageable design decisions met each other and became remote arbitrary file theft.

The remaining problem for an attacker was getting an instruction file onto the victim's computer at a known location. Telegram handled that too. By default, Telegram Desktop automatically downloaded group attachments up to 8 MiB into a predictable folder. Relative paths could reach that folder without knowing the victim's Windows username. The attacker could therefore send instruction files to a group, wait for Telegram to download them, and send a crafted link telling Telegram to interpret them.

The files could include Telegram's own local session data. By default, Telegram Desktop has no local passcode, so obtaining the relevant encrypted files and stored salt was enough to reconstruct the keys and take over the account. The flaw affected Telegram Desktop through version 7.2.8 and was fixed in 7.2.9.

The vulnerability chain was therefore: Telegram automatically downloads the attacker's instructions, the victim clicks one link, an unescaped semicolon turns the link into internal commands, and Telegram's release-publishing tool sends the victim's login files to the attacker. The software did not merely contain the vulnerability. It helpfully distributed, parsed and executed the paperwork.

3. Telegram Desktop vulnerability allowed any user's file to be stolen

beaksec.github.io | g-b-r | 191 points | 91 comments | discussion

First seen: October 10, 2026 | Consecutive daily streak: 1 day

Analysis

A vulnerability in Telegram Desktop through version 7.2.8 allowed a single clicked link to inject commands into the already-running client through its local IPC socket. By combining unescaped command separators with Telegram’s internal `interpret:` feature, attackers could make the application read arbitrary local files and upload them to an attacker-controlled chat, including session data. On systems without a Telegram local passcode, stolen files could be used to reconstruct the victim’s session and take over the account. Telegram fixed the issue in version 7.2.9 by removing the legacy file-sending mechanism and properly escaping IPC data; users should upgrade and consider disabling automatic downloads.

Analysis

Cloudflare is acquiring Deno, bringing its entire team into Cloudflare to develop a shared platform based on Workers, Durable Objects, and Deno’s “celld” distributed-application model.
