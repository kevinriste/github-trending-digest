Free computer science

Carnegie Mellon is putting computer science lectures on YouTube for free:

"Watch our faculty teach across AI, robotics, systems, biology, and more, from seven departments that lead their fields."

The initial offering includes Machine Learning with Large Datasets, Principles of Computing, AI Agents, Machine Learning in Production and various other courses. More courseware is coming, with instant feedback, badges and eventually AI tutoring "to help you work through questions and get unstuck."

This is the natural unbundling of a university education. The lectures are information, information has near-zero marginal distribution cost, and putting videos on YouTube is cheap. The scarce products are grading, credentials, access to professors, admission to Carnegie Mellon and being physically surrounded by other people who were admitted to Carnegie Mellon. So CMU can give away the part where a professor explains machine learning to anyone with an internet connection, while separately offering "graded work and an official credential through CMU Online" and the traditional full-time-student experience in Pittsburgh.

Also, increasingly, the free lectures will teach you how to build the AI tutor that helps you understand the free lectures. Eventually the AI tutor will watch the lectures, do the coursework and earn the badge. You can supervise, if you want the educational experience.

Verified by Claude

Anthropic says that about 90% of the Claude Code team's code is written and reviewed by Claude. This creates an obvious quality-control problem, whose solution is more Claude:

"Verification loops are the building block that lets you delegate more work to Claude. Without them, you can really only run one or two Claudes at a time, because you have to check everything yourself. With them, you can run dozens or hundreds in parallel."

Sure. If one AI writes code and another AI checks it, you can operate an AI software factory without reading every line yourself. Anthropic says that using a separate grader improved success on structured-file tasks by up to 10 points, with the largest gains on difficult problems. The basic insight is not especially alien: Programmers write code, tests check the code, and reviewers check both. The new feature is that the programmers, test writers and reviewers are all potentially the same species of robot.

The difficult part is preventing the robot from gaming the robot. Anthropic recommends end-to-end tests because "either the whole feature works or it doesn't," property tests that generate edge cases, and differential tests that compare old and new systems on the same inputs. It also keeps review rules on a branch that the proposed change cannot modify. "If a change can modify the check that judges it, the check is broken." Sensible constitutional design for the republic of coding agents.

There are escalation procedures. Claude tries to repair failed checks, but "if a check is still failing after three rounds, Claude stops and brings in a human." Commits can be blocked if the session did not include verification or code review. But if commits have been blocked twice, the next one is allowed through so Claude does not get stuck.

This is also sensible, in a way. A perfectly rigid automated control can halt production forever, so eventually you need an exception. Still, "the safety system rejected the robot twice, so on the third attempt we let it through" has a certain robot-safety-system quality to it.

Anthropic also says that if Claude cannot find the cause of a flaky test, it deletes the test and records why. Again, this is defensible software engineering. Again, it is also exactly what you would expect the robot to propose after the test catches it too many times.

Verification Becomes the AI Codebase’s Spine

Technical Analysis

The article explains how Anthropic’s Claude Code team uses layered verification to safely scale AI-written software, with roughly 90% of its code generated and reviewed by Claude. It recommends reliable, fast end-to-end checks as the primary safeguard, supplemented by property tests for edge cases and differential tests for migrations, while giving agents tools to run applications in realistic environments. The team protects verification rules from being modified by the code under review, runs inexpensive checks before shared CI and human review, escalates persistent failures, and records how each commit was verified. It also evaluates reviewers against real incidents, reverts, and stable changes, turning missed bugs into rules while pruning flaky or obsolete checks. This matters because strong, independently maintained feedback loops can replace exhaustive manual inspection with evidence-based oversight while enabling many agents to work in parallel.

Japan Turns Local Taxes Into A Marketplace

kalzumeus.com  ·  61 pts  ·  24 comments

Japan’s Hometown Tax lets residents redirect part of their future residence tax to municipalities of their choice. What began as regional redistribution became a nationwide catalog of food, travel, and municipal rewards.

Read →Share →
[ Analysis + ]

Technical Analysis

Japan’s Hometown Tax system lets residents redirect up to roughly 40% of their future residence tax to any municipality, aiming to compensate rural areas that educate workers who later move to Tokyo and other major cities. Municipalities initially offered modest local gifts, but competition and online brokerage platforms turned the program into an e-commerce marketplace featuring food, travel vouchers, and other rewards worth up to about half the donation. Participation grew from 33,000 people in 2008 to 2.2 million in 2016, with intermediaries collecting fees while cities gained revenue and contact with former residents. The system is important because it demonstrates how an opt-in tax transfer, cultural gift norms, and market incentives can reshape public finance, while also creating inefficiency and pressure for central-government limits.

Nimony Builds A New Nim Foundation

nimony.org  ·  82 pts  ·  29 comments

Nimony is a new compiler for Nim 3. Borrow checking, explicit nilability, sum types, native code generation, and WebAssembly support arrive in a pipeline designed to reduce old toolchain dependencies.

Read →Share →
[ Analysis + ]

Technical Analysis

Nimony is a new compiler for Nim and the foundation of the proposed Nim 3 language, offering features such as borrow checking, explicit nilability, sum types, checked generics, and exhaustive pattern matching. It includes an independent native code generator for several desktop, embedded, and RISC-V/AVR targets, as well as compilation to C, JavaScript, and WebAssembly, reducing reliance on LLVM, GCC, and C toolchains. The project emphasizes memory and type safety, bounds-checking contracts, incremental and parallel builds, and an extensible compiler pipeline based on the NIF interchange format. Its importance lies in positioning Nim as a more verifiable systems-to-full-stack language while addressing longstanding safety, portability, and tooling concerns, though the project remains an evolving nightly release.

A Trusted Script Pipeline Served Malware

blog.report-uri.com  ·  397 pts  ·  165 comments

Optimizely customer JavaScript was compromised, sending malicious code through sites including Zoom, GitLab, the BBC, and CNN. The payload targeted cryptocurrency, payment data, cookies, screenshots, and iOS users. Audit third-party scripts; restrict their reach.

Read →Share →
[ Analysis + ]

Technical Analysis

Attackers compromised customer-configured JavaScript in the Optimizely Web experimentation platform, causing malicious code to be served through trusted snippets on 178 organizations’ websites, including Zoom, the BBC, CNN, Salesforce, GitLab, and IKEA. The payload swapped cryptocurrency addresses, skimmed payment-card data, stole cookies and screenshots, and delivered iOS exploit kits, with at least about $7,000 in cryptocurrency traced to the attackers. The incident demonstrates the supply-chain risk of third-party browser scripts: affected sites and the Optimizely CDN itself did not need to be directly breached for visitors to receive malware. Most snippets were cleaned within hours, but the report emphasizes monitoring script changes and external connections, enforcing restrictive Content Security Policies, rotating potentially exposed credentials and tokens, and investigating affected transactions and user data.
