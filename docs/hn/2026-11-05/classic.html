The HN Take

Base model

Baidu released ERNIE-5.5-Flash-Base, a sparse mixture-of-experts model with 280 billion total parameters, 14 billion activated per token, and a one-million-token context window for fine-tuning and inference.

The important word is "Base." These are the weights "at the end of pre-training, before any mid- or post-training," so the model has absorbed 33.5 trillion tokens but has not yet been taught to behave like a useful assistant. Baidu has done the extremely expensive part and released the model at the point where developers can begin doing the merely expensive part.

This is appealing because different users want different things. Some want domain adaptation, some want instruction tuning, some want reasoning, and some want agents. Baidu's pitch is that it will provide the general intelligence substrate and let everyone install their own personality problems.

The architecture is optimized around that future work. Most layers compress every 128 old tokens into one cached entry, while one layer in seven retains token-level access to the full context. The model therefore remembers the distant past mostly as a summary, but periodically checks the original conversation. A relatable cognitive architecture.

Also numbers are tokenized right-to-left in groups of up to three digits, so place values line up across numbers of different lengths. Humanity spent decades teaching language models to read text, and the breakthrough in arithmetic was apparently commas.

Root factory

OpenAI built an autonomous pipeline that looks for Linux kernel vulnerabilities, reproduces them, develops working exploits and proposes patches. In one run, it generated 948 local privilege escalation exploits at an API cost of about $1.2 million, or $1,279 per path to root.

The system started with 2,308 candidate findings, dynamically reproduced 1,724 vulnerabilities and produced the 948 working exploits. It also generated root-cause analyses, minimal crashing proofs of concept and candidate patches for human review. So the product is a machine that breaks into the computer, explains how it broke into the computer and leaves a suggested repair on the way out.

OpenAI compares the cost with historical Linux kernel bug bounties of $20,000 to $70,000. At those prices, the exploits would have a hypothetical value of $18.9 million to $66.3 million, versus $1.2 million to produce them. This is not quite an arbitrage because bounty programs generally do not promise to buy 948 vulnerabilities from one industrial-scale vulnerability factory. Still, if finding security flaws costs $1,279 and a representative bounty is tens of thousands of dollars, someone will eventually notice the unit economics.

The operational bottleneck was no longer discovery but prioritization and validation. There were too many findings for researchers to review manually, so the pipeline had to automate the process of proving which automated discoveries were real. Artificial intelligence has solved the shortage of security work by creating more security work than humans can process.

OpenAI's conclusion is that automated patch generation is essential because frontier models can discover vulnerabilities faster than defenders can fix them. It also says that a low-privileged account on an operating system that is not fully patched should be considered "functionally equivalent to root access for a well-resourced threat actor."

Traditionally, getting a low-privileged account was the beginning of an attack. Now it is apparently the part before you spend $1,279.

1. Baidu released ERNIE 5.5 Flash Base

ernie.baidu.com | pretext | 57 points | 33 comments | discussion

First seen: November 05, 2026 | Consecutive daily streak: 1 day

Analysis

Baidu released ERNIE-5.5-Flash-Base, an unaligned 280-billion-parameter sparse MoE language model that activates 14 billion parameters per token and is intended as a starting point for fine-tuning, reasoning, and agent research. Trained on 33.5 trillion tokens with 128K pretraining context and support for up to 1 million tokens in inference and fine-tuning, it emphasizes lower training, inference, and long-context costs through hybrid sparse attention, latent experts, and other architectural optimizations. Baidu says the model performs competitively across exams, reasoning, coding, multilingual, and long-context benchmarks against similarly sized public base models, though results vary by task. The weights are available in FP8 and BF16 formats under Baidu’s model license, giving developers a ready-made alternative to undertaking large-scale pretraining themselves.

Analysis

The story reports that an IP address associated with the White House network appeared in a commercial residential-proxy service, which sells access to internet connections assigned to ordinary users and organizations. Such proxy networks can be used to mask the origin of automated activity, bypass access controls, or conduct fraud, while the connection owner may not realize their bandwidth is being shared. The finding does not by itself prove that the White House was compromised, since proxy providers may obtain access through bundled software, compromised devices, or third-party networks. It highlights the security and accountability problems created by the growing business of monetizing residential internet connections.

5. A thousand fewer paths to root

First seen: November 05, 2026 | Consecutive daily streak: 1 day

Analysis

OpenAI describes an autonomous security pipeline that scanned selected Linux kernel code, validated vulnerabilities, developed exploits, and generated candidate patches, with human researchers reviewing the results. In a mid-October 2026 run, it reduced 2,308 static findings to 1,724 reproduced vulnerabilities and 948 working local privilege-escalation exploits, at an API cost of about $1.2 million, while also identifying novel exploitation techniques. The work suggests frontier models can make vulnerability research economically scalable—potentially costing far less than historical bug-bounty valuations—but highlights that validation, attribution, patch quality, prioritization, and maintainer coordination remain essential. Its significance is that attackers may soon automate discovery and exploitation at similar scale, making rapid patching, repeated automated audits, hardened isolation, and high-assurance software increasingly important.

8. Partial Operator Precedence

ziglang.org | tosh | 60 points | 31 comments | discussion

First seen: November 05, 2026 | Consecutive daily streak: 1 day

Analysis

Zig’s latest devlog details a major language change, “partial operator precedence,” requiring parentheses for ambiguous operator combinations while preserving familiar precedence for common arithmetic and logical expressions. It also introduces safer and more manageable package tooling, including metadata and path filters for packages without manifests, hash consistency checks, dependency-tree visualization, and moving package management into the separate build-system process. The standard library gains pointer-stability checks for `ArrayList`, helping detect use-after-reallocation bugs, while the SPIR-V backend receives improved type support, calling conventions, capabilities handling, parallel code generation, and linking. Additional work improves LLVM integer lowering and `@bitCast` semantics, collectively aiming to make Zig code less error-prone, package builds more diagnosable, and compiler backends more robust.

Comment Analysis

The discussion centers on whether Zig’s partial-precedence approach is a useful middle ground: it retains familiar infix notation while requiring parentheses for some potentially ambiguous operator combinations. Commenters also debate the readability of operators versus functions, alternatives to precedence, and how operator rules compare across languages.

Partial precedence as a compromise — These commenters favor keeping familiar operators while requiring parentheses for combinations that could otherwise be ambiguous. Some see the approach as useful beyond Zig.
