Foundry // Prompt Engineering

Force AI coding agents to prioritize technical clarity

github.com  ·  36,371 stars  ·  4,650 stars today

The i-have-adhd plugin strips away conversational filler to deliver raw, actionable code solutions. By enforcing a strict rule set, it forces LLMs to stop the preamble and start the execution.

Read →Share →
[ Analysis + ]

ayghri/i-have-adhd ↗

Technical Analysis

The `i-have-adhd` repository provides a specialized skill plugin for coding agents, such as Claude Code and Codex, designed to optimize LLM responses for efficiency and clarity. By enforcing a strict set of ten rules—such as prioritizing immediate actions, utilizing numbered lists, and eliminating conversational filler like preambles or closers—it forces the AI to cut straight to the technical solution. Technically, the tool functions as a system-prompt modifier that can be installed directly through plugin marketplaces, requiring no local cloning to operate. Users can trigger this behavior explicitly via a command or allow the agent to invoke it implicitly when a task demands high-density information. Additionally, the plugin is highly customizable, allowing users to fork the repository and tweak the core operational rules in `SKILL.md` to suit their specific workflow requirements.

This project is primarily intended for developers who struggle with the verbose, conversational nature of standard AI assistants and prefer a streamlined, "just the facts" interaction model. It is gaining traction because it addresses a common pain point: the frustration of scrolling past excessive polite fluff to find the actual code or command required to solve a problem. By shifting the AI’s communication style to be task-oriented and objective, the plugin minimizes cognitive load and keeps developers in a state of flow. Its popularity highlights a broader movement toward "ADHD-friendly" computing, where users are actively seeking ways to reduce digital distractions and improve the precision of their productivity tools. Ultimately, it serves as an essential utility for anyone looking to maximize their development speed by stripping away unnecessary text.

[ Analysis + ]

bilawalsidhu/gods-eye-view ↗

Technical Analysis

God's Eye View is an open-source, browser-based simulation that transforms real-time public telemetry data into a photorealistic 3D globe experience. By aggregating data from flight transponders, ship beacons, orbital elements, and live public cameras, the platform allows users to track global movement with high-fidelity visualization. The project features sophisticated capabilities like a tactical cockpit view, an AI-powered voice assistant for hands-free navigation, and various sensor overlays such as FLIR and night vision. Technically, the application runs directly in the browser and leverages modular API integrations to render its environment, distinguishing between live sensor data and reconstructed simulations. Its codebase is fully inspectable, ensuring that users understand how each data layer is sourced, processed, and visualized on the map.

This project appeals to open-source intelligence (OSINT) enthusiasts, developers, and tech hobbyists who seek a sophisticated interface for exploring global real-time data. It is trending because it democratizes access to professional-grade geospatial tools that previously appeared reserved for high-budget government or military simulations. Users benefit from the platform’s ability to consolidate fragmented browser-based tracking into a single, immersive environment, making complex global activity intuitive and accessible. The project’s virality is driven by its "forbidden cockpit" aesthetic and the transparency of its open-source nature, which encourages community extensions and experimentation. Ultimately, it serves as a powerful demonstration of how public signals can be synthesized into an engaging, high-utility interface.

Foundry // Workflow Standards

Impose professional discipline on autonomous AI coding agents

github.com  ·  284,363 stars  ·  688 stars today

Superpowers injects mandatory TDD and multi-stage review processes into your AI development lifecycle. It prevents common agent drift, ensuring every generated commit adheres to strict engineering principles.

Read →Share →
[ Analysis + ]

obra/superpowers ↗

Technical Analysis

Superpowers is an agentic skills framework designed to standardize the software development lifecycle across various AI coding assistants, including Claude Code, Cursor, and the GitHub Copilot CLI. Technically, it functions as a modular plugin system that enforces a rigorous methodology—incorporating Socratic brainstorming, mandatory Test-Driven Development (TDD), and systematic task decomposition—before any code is written. By injecting a set of composable skills into the agent’s session, it compels the AI to create detailed implementation plans and perform autonomous, multi-stage code reviews. The framework relies on a structured workflow, such as subagent-driven development and git worktree isolation, to ensure that coding agents operate with persistence and architectural discipline. Ultimately, it shifts the agent's behavior from impulsive coding to a verified, process-driven execution model.

Software developers and enterprise engineering teams who struggle with the erratic, hallucination-prone, or ad-hoc nature of current AI coding tools will find this framework highly beneficial. It is trending because it addresses the core frustration of "agent drift," where AI models often lose context or ignore testing standards during complex multi-hour tasks. By imposing a professional, disciplined development process, Superpowers transforms high-level prompts into granular, testable, and reliable outcomes. It is particularly valuable for developers who want to scale the effectiveness of their AI assistants without abandoning strict engineering principles like YAGNI and DRY. As the landscape of AI-assisted coding shifts from simple autocomplete to autonomous agentic systems, this project provides the necessary governance to make such automation actually viable for production environments.

alsk1992/CloddsBot ↗

Technical Analysis

CloddsBot is a comprehensive, self-hosted AI trading terminal designed to autonomously execute trades and manage portfolios across 1000+ markets, including prediction platforms, crypto spot, and perpetual futures. Technically, the system is powered by Claude and features a modular architecture that integrates with 21 messaging platforms and a built-in, browser-based WebChat interface. This project is primarily intended for sophisticated crypto traders, algorithmic developers, and DeFi enthusiasts who seek to leverage AI-driven automation for competitive market analysis and execution. It is currently trending because it offers a "no-code" conversational interface for high-frequency tasks that typically require complex scripting, effectively democratizing access to institutional-grade trading strategies. The bot's ability to seamlessly bridge prediction markets with native Solana and EVM DeFi protocols makes it a unique, all-in-one hub for the modern crypto power user. Its success in the Colosseum Agent Hackathon further signals its status as a robust, battle-tested solution in the rapidly expanding sector of autonomous machine-to-machine commerce.

Tencent/teamai-cli ↗

Technical Analysis

TeamAI is a CLI-based infrastructure tool designed to unify team-wide AI workflows by synchronizing skills, rules, and knowledge across popular AI agents like Claude Code, Cursor, and CodeBuddy. Technically, it functions by leveraging a centralized Git repository as a "Harness" that distributes standardized configurations, documentation, and agent hooks to individual team members' environments. Through a "push-review-merge" workflow, admins can propagate updates automatically, ensuring every team member operates with the latest environment variables, role-based skills, and project-specific best practices. Beyond simple synchronization, the project features a "Team Context" layer that uses friction-based telemetry to identify recurring challenges and automatically suggests documentation for shared learnings. It also integrates a searchable knowledge graph, generated via AST parsing and heuristic analysis, to provide AI agents with context-aware information retrieval across the entire codebase.

This project is primarily intended for engineering organizations and development teams that want to standardize their AI-assisted workflows and reduce the overhead of manual prompt engineering. It is particularly beneficial for distributed teams, as it ensures consistent behavior and technical alignment across diverse AI tools used by different developers. The project is currently trending because it addresses the critical "fragmentation" problem in the AI-native development space, where tribal knowledge and custom prompts often remain siloed within individual local environments. By transforming institutional knowledge into a structured, code-accessible format, TeamAI effectively democratizes the expertise of senior engineers. As organizations race to integrate LLMs into their CI/CD pipelines and coding practices, tools that provide a "single source of truth" for agentic behavior are becoming essential for maintaining developer velocity and technical quality.

Weights // Hardware Benchmarking

Identify the perfect local LLM for your specific hardware

github.com  ·  35,483 stars  ·  247 stars today

Llmfit analyzes your CPU and GPU specs to predict which large language models will run efficiently. It removes the guesswork from local inference by providing data-driven performance estimates.

Read →Share →
[ Analysis + ]

AlexsJones/llmfit ↗

Technical Analysis

`llmfit` is a terminal-based utility designed to analyze a user's hardware—including RAM, CPU, and GPU specifications—to determine which Large Language Models (LLMs) can run effectively on their system. The tool provides a comprehensive TUI and CLI interface that scores models based on memory fit, estimated performance, quality, and context window capabilities. Technically, it leverages a memory-bandwidth model to generate performance estimates, which are refined through real-world community benchmarking data. It supports various runtime providers, including Ollama, llama.cpp, MLX, and Docker, allowing users to move from recommendations to execution seamlessly. By allowing users to benchmark their own hardware and share the results via PRs, the project continuously improves the accuracy of its recommendations for the entire community.

This project is an invaluable resource for developers, AI researchers, and hardware enthusiasts who want to optimize their local LLM workflows without the guesswork of manual testing. It is particularly beneficial for those managing diverse hardware setups, as it eliminates the frustration of downloading massive models only to find they exceed system memory or underperform due to architecture incompatibilities. The project is trending because it addresses the significant "discovery friction" in the rapidly expanding local AI ecosystem, where choosing the right model for specific hardware constraints is often opaque. By providing verifiable, data-driven insights rather than generic estimates, `llmfit` empowers users to make informed deployment decisions. Its ability to integrate into automated scripts via JSON output further cements its utility for users building agents or custom LLM infrastructure.
